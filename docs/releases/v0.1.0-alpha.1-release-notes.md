## What is Floe?

Floe is a plugin-driven data platform that compiles declarative configuration
into data infrastructure on Kubernetes. Platform engineers deploy via Helm;
data engineers build products by editing `floe.yaml`.

This is the first alpha release. APIs are unstable and will change before 1.0.

## Alpha Capabilities

### Core Platform

- **Two-file configuration model**: `manifest.yaml` for platform configuration
  and `floe.yaml` for data-product configuration
- **Plugin system**: 14 plugin categories with entry-point discovery, ABC interfaces,
  and independent package versioning
- **CLI**: `floe platform compile` and `floe platform deploy` for platform
  compilation and deployment workflows
- **Four-layer architecture**: Foundation (PyPI) -> Configuration (OCI) ->
  Services (K8s) -> Data (K8s Jobs)
- **CompiledArtifacts contract**: cross-package integration point between
  `floe-core` and downstream consumers

### Kubernetes Deployment

- **Helm charts**: `charts/floe-platform` and `charts/floe-jobs`
- **Helm release policy**: `helm-release.yaml` may release only the chart paths
  declared in `release/floe-release.yaml` when `helm.alpha_policy` allows it
- **Bundled services**: Dagster, Polaris, MinIO, PostgreSQL, Marquez, Jaeger,
  and OpenTelemetry Collector
- **GitOps manifests**: Flux v2 HelmRelease resources for local Kubernetes
  validation paths

### Observability

- OpenTelemetry traces across compilation, deployment, and execution
- OpenLineage lineage events to Marquez
- Structured logging via structlog

### Demo: Customer 360

The alpha evidence gate requires Customer 360 validation with Iceberg enabled:

- dbt models compiled and executed via Dagster
- Iceberg tables written through the validated storage/catalog path
- Lineage events posted to Marquez
- Traces exported to Jaeger

## Release Evidence Gate

Before the tag is pushed, maintainers must record:

- current `main` release SHA
- manifest validation for `v0.1.0-alpha.1`
- package build dry-run for the 15 manifest packages
- current-main CI and required release checks
- full DevPod+Hetzner E2E from current `main`
- AWS S3+Glue live validation, or manifest-recorded accepted evidence
- AWS and Hetzner cleanup evidence
- post-publish PyPI verification for exactly the manifest package set
- Helm behavior verification against the manifest policy

## Known Limitations

- **Pre-1.0 API instability**: MINOR version bumps may include breaking changes.
- **Iceberg coupling**: Dagster integration currently requires `floe-iceberg`.
  Decoupling is tracked as [#263](https://github.com/Obsidian-Owl/floe/issues/263).
- **Excluded plugins**: Alert, identity, secret, Cube semantic layer, dbt Fusion,
  console telemetry, and dbt-expectations packages are not part of the alpha
  PyPI publish cutline.
- **Linux validation**: The alpha release gate is Linux-based. Windows and macOS
  validation are outside this alpha gate.
- **No structured changelog**: This release uses release notes and GitHub
  generated change summaries. Structured changelogs are a later release concern.
